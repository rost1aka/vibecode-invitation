# Vibecode Invitation — Design Spec

**Дата:** 2026-09-28
**Статус:** на рев'ю

## 1. Мета

Персональна вебсторінка-запрошення, щоб покликати друга повайбкодити разом. Автор генерує посилання з імʼям друга, локацією та часовими вікнами; друг відкриває сторінку, погоджується (іншого вибору немає — кнопка «Ні» тікає), обирає зручний час і додає подію в Google Calendar. Автор дізнається про вибір через інвайт у календарі та, як страховка, через повідомлення в Telegram.

### Критерії успіху

- Автор створює запрошення на сторінці-конструкторі `/create`: вводить імʼя, локацію, тривалість і таймслоти — і отримує готове посилання, яке копіює й надсилає другу.

- Сторінка відображає імʼя друга з URL у тексті запрошення **у кличному відмінку** (Андрій → «Андрію», Олена → «Олено», Тарас → «Тарасе»).
- Кнопку «Ні» неможливо натиснути ні мишкою, ні пальцем, ні клавіатурою.
- Після «Так» друг бачить «Супер, я знав, що ти погодишся!» і може обрати один із запропонованих слотів.
- Після вибору друг бачить підтвердження, що вайбкодинг-сесію заплановано, і кнопку «Додати в Google Calendar», яка створює подію з автором як гостем.
- Автор отримує Telegram-повідомлення про згоду, обраний час і натискання кнопки календаря.
- Лише на першому екрані (запрошення) є текст «not a big deal, зробив цей додаток поки пив каву»; на екранах вибору часу та підтвердження його немає.

### Поза межами (YAGNI)

- Авторизація, база даних, адмінка, збереження створених запрошень (конструктор лише генерує посилання).
- Збереження стану між відвідуваннями.
- Мультимовність (інтерфейс — українською).

## 2. Стек і хостинг

- **Фронтенд:** Vite + TypeScript, vanilla DOM (без фреймворку).
- **Бекенд:** одна Vercel serverless function `api/notify.ts`.
- **Хостинг:** Vercel (Hobby). Фронтенд і `/api` на одному домені — без CORS.
- **Тести:** Vitest.
- **Репозиторій:** публічний, `github.com/rost1aka/vibecode-invitation`.

## 3. URL-параметри

| Параметр | Обовʼязковий | Формат | Поведінка при відсутності / помилці |
|---|---|---|---|
| `name` | ні | рядок, обрізається до 40 символів | звертання «Друже» |
| `location` | ні | рядок, обрізається до 100 символів | блок локації не показується |
| `slots` | ні | ISO 8601 з offset через кому, напр. `2026-10-01T18:00+03:00` | невалідні та минулі слоти відкидаються; максимум 12; якщо валідних немає — див. нижче |
| `duration` | ні | хвилини, ціле 15–480 | 120 |
| `gender` | ні | `m` або `f` | визначається автоматично за імʼям |
| `vocative` | ні | готова форма звертання, до 40 символів | обчислюється автоматично з `name` |

Приклад:

```
https://vibecode-invitation.vercel.app/?name=Андрій&location=Lviv%20IT%20Park&slots=2026-10-01T18:00%2B03:00,2026-10-02T19:30%2B03:00
```

> `+` в offset треба кодувати як `%2B`, інакше браузер прочитає його як пробіл. Парсер додатково трактує пробіл перед `HH:MM` в кінці слоту як `+` — для зручності при ручному складанні посилань.

### Кличний відмінок

`name` передається **у називному відмінку** (як імʼя записане в паспорті: `Андрій`). На сторінці звертання завжди в **кличному відмінку**:

1. Якщо задано `vocative` — використовується як є (для складних випадків, зменшувальних форм, прізвиськ: `vocative=Андрійку`).
2. Інакше `name` відмінюється бібліотекою [`shevchenko`](https://github.com/tooleks/shevchenko-js) (MIT): стать береться з `gender` або визначається через `shevchenko.detectGender`; далі `shevchenko.inVocative({ gender, givenName })`.
3. Якщо стать не визначилась, імʼя не кириличне (`Alex`), або бібліотека кинула помилку — показується `name` без змін.
4. Без `name` — «Друже» (вже кличний).

Модуль `src/vocative.ts` експортує `toVocative(name, gender?, override?) → Promise<string>`. Бібліотека важка (~1 MB unpacked), тож імпортується динамічно (`import('shevchenko')`) — окремий chunk; поки він вантажиться, заголовок не показується (сторінка має легкий fade-in), щоб не було «стрибка» з «Андрій» на «Андрію».

У Telegram-повідомленнях використовується `name` у **називному** відмінку («Андрій погодився…»).

**Без валідних слотів:** після «Так» замість вибору часу показується «Супер, я знав, що ти погодишся! Напиши мені, коли тобі зручно» і одразу відправляється подія `accepted`.

**Конфіг автора** (не в URL):

- `VITE_HOST_EMAIL` — email автора, додається гостем у подію календаря. Задається як env-змінна у Vercel (і в `.env.local` локально), не комітиться.

## 4. Флоу автора

### 4.1. Одноразове налаштування

1. Задеплоїти репозиторій на Vercel (Import Project → Vite визначається автоматично).
2. Створити Telegram-бота через [@BotFather](https://t.me/BotFather), отримати токен; написати боту будь-яке повідомлення й дізнатись свій `chat_id` через `https://api.telegram.org/bot<TOKEN>/getUpdates`.
3. У Vercel → Project Settings → Environment Variables додати `VITE_HOST_EMAIL`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` і зробити redeploy.

### 4.2. Створення запрошення

1. Автор відкриває `https://<домен>/create`.
2. Заповнює форму:

   | Поле | Контрол | Правила |
   |---|---|---|
   | Імʼя друга | text, обовʼязкове | у називному відмінку, до 40 символів → `name` |
   | Звертання | text | автозаповнюється через `toVocative` при зміні імені/статі; якщо автор відредагував вручну — ручне значення фіксується і більше не перезаписується (кнопка «↺» повертає авто). У URL потрапляє як `vocative` **лише** якщо відрізняється від автоматичного |
   | Стать | radio: авто / ч / ж | «авто» → параметр не додається; інакше `gender=m\|f` |
   | Локація | text | до 100 символів → `location` |
   | Тривалість | select: 30 / 60 / 90 / 120 / 180 / 240 хв | за замовчуванням 120; у URL лише якщо ≠ 120 |
   | Таймслоти | список `<input type="datetime-local">` + «+ додати слот» / «✕» | див. нижче |

3. Під формою в реальному часі оновлюються:
   - прев'ю заголовка: «Андрію, давай повайбкодимо разом? 🤖☕»;
   - згенероване посилання (read-only поле);
   - кнопки **«Скопіювати»** (`navigator.clipboard.writeText`, fallback — виділення тексту; після копіювання «Скопійовано ✓» на 2 с) і **«Переглянути»** (відкриває посилання в новій вкладці).
4. Автор копіює посилання і надсилає другу будь-яким месенджером.
5. Далі автор отримує Telegram-повідомлення (§7) і, якщо друг зберіг подію, інвайт у Google Calendar (§6).

### 4.3. Таймслоти в конструкторі

- Кожен слот — початок сесії, вводиться в **локальному часі браузера автора** (`datetime-local`, крок 15 хв).
- Конвертація в URL: `new Date(value)` → ISO з offset автора **на дату слоту** (коректно для переходу на літній/зимовий час), напр. `2026-10-01T18:00+03:00`, `2026-11-02T18:00+02:00`.
- При генерації посилання слоти сортуються, дублікати прибираються, порожні ігноруються.
- Слот у минулому підсвічується помилкою «Цей час уже минув» і в посилання не потрапляє.
- Максимум 12 слотів — кнопка «+ додати слот» ховається.
- Під списком підказка: «Час у твоєму поясі ({timeZone}). Друг побачить його у своєму».
- Нуль слотів — дозволено, з попередженням: «Без слотів друг просто напише тобі, коли зручно».

### 4.4. Ручне складання посилання

Конструктор — зручність, а не обовʼязок: посилання можна скласти вручну за правилами §3 (README містить приклад).

### 4.5. Технічні деталі конструктора

- Vite multi-page: `index.html` (запрошення) і `create.html` (конструктор) — два entry у `build.rollupOptions.input`.
- `vercel.json` з `"cleanUrls": true`, щоб `/create` віддавав `create.html`.
- `create.html` має `<meta name="robots" content="noindex">`; посилання на `/create` зі сторінки запрошення немає.
- Конструктор не має секретів і бекенду; він публічний. Хтось сторонній може ним скористатись, але запрошення все одно додаватимуть гостем автора — ризик прийнятний.
- Генерація посилання — чиста функція `buildInvitationUrl(origin, params)` у `src/link.ts`; гарантія узгодженості: `parseParams(buildInvitationUrl(x))` ≡ `x` (round-trip тест).

## 5. Флоу друга

Одна сторінка, три стани (екрани), перемикаються без перезавантаження.

### Екран 1 — Запрошення

- Заголовок: «{імʼя в кличному відмінку}, давай повайбкодимо разом? 🤖☕» — напр. «Андрію, давай повайбкодимо разом? 🤖☕».
- Якщо є `location`: «📍 {location}» — посилання на `https://www.google.com/maps/search/?api=1&query={location}`.
- Кнопки **Так** і **Ні**.
- Футер (лише на цьому екрані): «not a big deal, зробив цей додаток поки пив каву». При переході на екран 2 футер ховається.

### Кнопка «Ні»

- Тригери втечі: курсор ближче ніж 100px до центру кнопки (`pointermove` на документі), `pointerenter`, `touchstart`, `pointerdown`, `focus`.
- Будь-який `click` / `keydown` (Enter, Space) на кнопці — `preventDefault()` + втеча. Жодна дія «відмови» не виконується в жодному разі.
- При першій втечі кнопка переходить у `position: fixed`.
- Нова позиція — чиста функція `nextPosition(viewport, buttonSize, pointer, random)`:
  - генерує до 20 випадкових кандидатів у межах вʼюпорту з відступом 16px від країв;
  - повертає першого, чий центр ≥ 200px від вказівника;
  - якщо жоден не підходить (малий екран) — повертає найвіддаленішого кандидата.
- Анімація переміщення 150ms; при `prefers-reduced-motion` — без анімації.
- Кожна втеча збільшує лічильник `noAttempts` (для Telegram-повідомлення).

### Екран 2 — Вибір часу

- Заголовок: «Супер, я знав, що ти погодишся! 😎»
- Підзаголовок: «Обери зручний час:»
- Слоти — картки-кнопки, відсортовані за часом, відформатовані `Intl.DateTimeFormat('uk-UA')` у часовому поясі браузера друга, напр. «чт, 1 жовтня · 18:00–20:00».
- Натискання на «Так» (перехід на цей екран) відправляє подію `accepted`.

### Екран 3 — Підтвердження

- Заголовок: «Вайбкодинг-сесію заплановано! 🎉»
- Текст: «{дата, час}» + локація, якщо є.
- Кнопка **«Додати в Google Calendar»** — відкриває в новій вкладці посилання (див. §6).
- Посилання «обрати інший час» — повертає на екран 2.
- Вибір слоту відправляє `slot_selected`; клік на кнопку календаря — `calendar_clicked`.

## 6. Google Calendar

Посилання формату:

```
https://calendar.google.com/calendar/render?action=TEMPLATE
  &text=Вайбкодинг-сесія 🤖☕
  &dates={startUTC}/{endUTC}          // YYYYMMDDTHHMMSSZ
  &details=Вайбкодимо разом 🤖☕
  &location={location}                // якщо є
  &add={VITE_HOST_EMAIL}              // якщо задано
```

Кінець = початок + `duration`. Усі значення кодуються через `URLSearchParams`.

**Відоме обмеження:** ми не можемо дізнатися, чи друг справді зберіг подію. Інвайт у календарі автора — фактичне підтвердження; `calendar_clicked` — лише найкращий доступний сигнал.

## 7. Telegram-страховка

### Клієнт (`src/notify.ts`)

`notify(event)` → `fetch('/api/notify', { method: 'POST', keepalive: true, body: JSON })`. Fire-and-forget: помилки ковтаються, UI ніколи не чекає і не показує помилок.

Payload:

```ts
type NotifyEvent =
  | { type: 'accepted'; name: string; noAttempts: number }
  | { type: 'slot_selected'; name: string; slot: string; timeZone: string }
  | { type: 'calendar_clicked'; name: string; slot: string };
```

`slot` — ISO-рядок з URL; `timeZone` — `Intl.DateTimeFormat().resolvedOptions().timeZone` друга.

### Сервер (`api/notify.ts`)

- Лише `POST`, інакше `405`.
- Тіло ≤ 2 KB, інакше `413`.
- Валідація: `type` з переліку, рядки обрізаються до 100 символів, `noAttempts` — ціле 0–10000. Невалідне — `400`.
- Формує текст і шле `POST https://api.telegram.org/bot{TELEGRAM_BOT_TOKEN}/sendMessage` з `chat_id = TELEGRAM_CHAT_ID`, без `parse_mode` (plain text — жодних ін'єкцій розмітки).
- Відповідь `204`; якщо Telegram повернув помилку — `502`; якщо env не задані — `500` (клієнт це ігнорує).

Повідомлення (час форматується у `Europe/Kyiv`, часовий пояс автора):

| type | текст |
|---|---|
| `accepted` | ✅ {name} погодився вайбкодити! (спроб натиснути «Ні»: {noAttempts}) |
| `slot_selected` | 🕐 {name} обрав час: {дата, час} (Київ). Пояс друга: {timeZone} |
| `calendar_clicked` | 📅 {name} натиснув «Додати в Google Calendar» на {дата, час} |

**Спам:** endpoint публічний, але `chat_id` зашитий на сервері, тож у гіршому разі спам отримує лише автор. Rate limiting — поза межами.

### Env-змінні Vercel

| Змінна | Де використовується |
|---|---|
| `TELEGRAM_BOT_TOKEN` | сервер |
| `TELEGRAM_CHAT_ID` | сервер |
| `VITE_HOST_EMAIL` | фронтенд (вбудовується при збірці) |

## 9. Тестування

- **Unit (Vitest):**
  - `params` — дефолти, `gender`/`vocative`, обрізання, `%2B`/пробіл в offset, відкидання невалідних/минулих слотів, ліміт 12, межі `duration`.
  - `calendar` — формат дат в UTC, кодування, наявність/відсутність `location` і `add`.
  - `dodge` — позиція завжди у вʼюпорті, ≥ 200px від вказівника коли можливо, fallback на малому екрані (детермінований `random`).
  - `format` — формат слоту для `uk-UA`.
  - `link` — кодування `+`/кирилиці, пропуск дефолтних параметрів, `vocative` лише коли відрізняється; round-trip з `parseParams`.
  - `slots` — offset з урахуванням DST, сортування, дедуплікація, відкидання минулих і порожніх.
  - `vocative` — Андрій→Андрію, Олена→Олено, Тарас→Тарасе, Микола→Миколо; `gender` впливає на результат; `override` має пріоритет; латиниця/помилка → імʼя без змін.
  - `api/notify` — 405/413/400/500/502/204, текст повідомлень, `fetch` до Telegram замоканий.
- **Ручна перевірка:** `vercel dev` у десктопному браузері та мобільній емуляції: конструктор `/create` (автозвертання, ручне перевизначення, додавання/видалення слотів, копіювання, «Переглянути»), неможливість натиснути «Ні» (миша, тач, Tab+Enter), повний флоу, посилання календаря, повідомлення в Telegram.

## 10. Прийняті рішення

- Vite + TS замість чистого JS — за бажанням автора.
- Vercel замість Render — одна платформа для статики й функції, без холодного старту в 30–50 с і без CORS.
- Google Calendar як основний канал + Telegram як страховка.
- Конструктор `/create` замість ручного складання URL — автору не треба памʼятати формат і кодування `+`.
- Кличний відмінок — автоматично через `shevchenko` + ручне перевизначення `vocative`, бо жодна бібліотека не покриває всі імена й зменшувальні форми.
- Email автора — через env, а не в URL чи коді, щоб не світити його в публічному репо (у зібраному JS він все одно буде видимий).
